# AI 获客：公开网页搜索与自动初筛

TradePilot `/app/prospecting` 的设计参考（**未复制第三方项目代码**）：

- [Firecrawl](https://github.com/firecrawl/firecrawl)（AGPL-3.0）：公开网页搜索 API；本次租户搜索只使用其独立 Firecrawl Cloud Key 和固定官方端点，不使用平台共享配置。
- [Tanchi](https://github.com/tanchihq/tanchi)（AGPL-3.0）：B2B 人设/线索研究、来源证据和可纠正的线索队列。其外呼/邮箱自动化没有集成进来。
- [Open Scouts](https://github.com/firecrawl/open-scouts)：提供定时网页监测思路；仓库根目录未见许可证，因此未复制代码，也未承诺其许可可用于本项目。

## 新手快速开始（先看这里）

### 先分清两项配置

- **Firecrawl 搜索服务**：负责“去哪里找公开网页”。请工作区所有者或管理员在本页「获客服务配置」填自己的 **Firecrawl Cloud API Key**、设置每日预算并启用。服务地址固定为 `https://api.firecrawl.dev`，不需要填 URL；搜索调用 `POST /v1/search`。不回退平台共享 Key、不接受任意自托管地址。
- **文本 AI 模型**：负责“根据线索写联系草稿”。普通租户请管理员到「AI 用量」配置自己的文本服务、模型 ID、Key、月预算并启用。这个配置不能代替搜索服务。仅平台管理员的实例文本操作走「API 配置中心」。
- Key 加密存入 PostgreSQL，页面不回显。没有工作区管理权限时请联系自己的工作区管理员；不要把 Key 发到聊天、日志、客户资料里。
- 每日实际请求上限取工作区预算与平台 `FIRECRAWL_TENANT_DAILY_REQUEST_LIMIT` 的最低值（默认 20），按 UTC 日计数。并发运行先原子预留；失败/超时也计入次数，避免反复失败产生无界成本。页面显示今日使用次数和平台上限；次数不是供应商金额账单。

### 再按页面操作

1. 创建 **业务人设**：例如“主营蓝牙耳机，寻找德国有消费电子采购经验的进口商”。主营业务写产品/优势，目标客户写买家类型与地区，风格可写“专业、简洁、友好”。
2. 创建 **线索筛选任务**：选择刚创建的人设，起一个好识别的任务名，例如“德国蓝牙耳机进口商”；关键词用逗号分隔，尽量放买家会写在网页上的词，如 `bluetooth headset importer, electronics wholesaler, Germany`。关键词过宽会增加无关结果。
3. 点击 **创建任务**，然后在任务卡片点击 **运行获客**。任务会搜索公开网页并最多处理 10 条结果；每个任务至少间隔 15 分钟。首次运行会实际调用 Firecrawl Cloud、可能消耗服务商额度；平台“测试连接”不会替租户验证 Key、搜索额度或预算。
4. 在 **线索结果** 查看来源链接和摘要。打开来源核实公司、业务和采购需求；分数是关键词规则的参考，不是 AI 对公司真实性或购买意愿的确认。误判时可以改状态/备注。
5. 只有你核实后，才把合适线索标记为高意向/跟进中并点 **转入客户库**。如果还要写联系内容，点 **生成草稿**，检查事实和联系许可，修改后自行复制、审核并发送。

没有 Firecrawl 时，仍可在“手动补录（可选）”里粘贴你有权处理的公开来源链接并登记线索。**不要**把个人敏感信息或不应提交给第三方模型的内容放入表单；生成话术会将有限的线索摘要和业务人设发送给已配置的文本模型，模型服务商可能按其政策留存/计费。

## 工作流

1. 创建人设与关键词任务。先在本页配置自己的 Firecrawl Cloud Key 与每日预算。
2. 点击任务的“运行获客”：最多获取 10 条公开网页搜索结果，检查来源 URL，要求标题与摘要，跨任务按规范化 URL 去重。仅存储标题/摘要，不主动抓取完整页面、不抽取邮箱、不自动登录平台。
3. 系统按关键词与人设匹配分数自动标记高意向（≥60）或不匹配（<60），记录来源、时间、理由；可人工纠正误判。搜索摘要不等同于企业身份或购买意愿验证。
4. 人工补录仍可用；AI 话术是可编辑草稿，**不会自动发送**。高意向线索可转入联系人库。

每个任务运行间隔至少 15 分钟；服务不可用/不支持搜索时显示错误，不制造演示数据。线索、人设、任务、运行状态和联系人按当前工作区保存到 PostgreSQL；URL 去重、任务冷却和业务写入使用数据库事务与工作区锁，不回退旧版哈希 JSON 文件。数据库不可用会明确失败。普通租户使用工作区独立 Firecrawl/AI Key 与预算；不会借用实例密钥。兼容产品抓取入口仍要求平台管理员，并且同时执行工作区预算和昂贵 API 限流。配置和备份见 [数据库管理指南](database-management.md)。

限制：没有定时后台任务、社媒账号自动化、评论/关注/私信、验证码处理、自动群发，亦不会从搜索摘要推断私人联系方式。生产使用前需按目标平台与地区核实数据处理、平台规则和发送合规性。

### 产品链接抓取与请求预算

`/api/firecrawl/preview` 与旧兼容入口 `/api/products/import` 使用同一处理器：两者都只允许平台管理员、读取当前工作区的 Cloud Key，且与“运行获客”的搜索请求共用每日预算。产品来源必须为公开 HTTP/HTTPS 链接；请求正文上限为 8,000 字节。成功、供应商失败和未完成的请求均计入预算；超额返回 429，不再联系供应商。请求预算按 UTC 自然日计算，是本系统的调用次数上限，**不是**供应商 credit/金额的精确账单。平台 API 配置中的自托管地址或共享 Key 仅用于实例诊断，不会作为这些租户业务请求的备用凭据。
