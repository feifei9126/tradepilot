# SaaS 多用户管理（初学者指南）

> 当前是**管理员邀请制的多工作区基础版**，不是已完成支付、订阅、自助注册和公网安全验收的商用 SaaS。自助注册继续关闭。上线状态见 `saas-launch-audit-2026-09-29.md` 的最新整改记录。

## 1. 先弄懂三个词

- **平台管理员**：部署这套系统的人。管理整个平台的工作区、数据库诊断与实例 API 密钥。
- **工作区（租户）**：一家客户公司自己的数据空间。同一家公司里的同事共享业务数据，不同公司不能互相查看。新建工作区不会带入平台的客户或共享演示数据。
- **团队成员**：在某个工作区中的登录账号。当前一个邮箱只能对应一个账号、一个工作区；没有多工作区切换。

菜单入口：平台管理员看到「SaaS 工作区」「数据库管理」；工作区所有者和管理员看到「团队管理」；所有用户都可使用「个人中心」。普通成员没有管理其他成员的权限。隐藏菜单**不是**权限控制，服务端仍会校验。

## 2. 从零创建一家客户公司

1. 按 `database-management.md` 部署并初始化 PostgreSQL。先登录部署管理员。
2. 打开 **SaaS 工作区**（`/app/saas`），填写公司名称、工作区标识、成员上限、所有者姓名和邮箱。
   - 工作区标识用小写英文字母、数字及连字符，例如 `acme-export`；不要放密码或客户隐私。
   - 成员上限**包括所有者**，按启用账号数量计算。停用成员不占活跃名额。
   - 所有者邮箱不能使用其他工作区已注册的邮箱。
3. 点击创建，系统会在同一事务中建立工作区、所有者和审计事件；失败不会留下半个账号。
4. **立即保存一次性显示的临时密码**，通过安全渠道交给所有者。刷新页面后无法再次查看明文；不要发到公共群、代码仓库或工单。
5. 所有者首次登录后进入 **个人中心 → 修改密码**，用临时密码作为原密码设置自己的新密码。修改后旧会话失效，需要重新登录。
6. 所有者进入 **团队管理**（`/app/team`）添加同事。新同事也要完成首次改密。

密码丢失：所有者或有权限的管理员可以给普通成员重置**新的**临时密码，不能查看旧密码。所有者本人密码通过个人中心修改；当前团队页不支持重置所有者、不支持所有权转移，也没有邮件找回。部署管理员的本地账号与工作区所有者不是同一套存储，不能用 `db:init --reset-password` 重置本地部署管理员。

## 3. 权限对照

| 操作 | 平台管理员 | 工作区所有者 owner | 工作区管理员 admin | 普通成员 member |
|---|---|---|---|---|
| 创建 / 启停工作区、调整成员上限 | 是 | 否 | 否 | 否 |
| 数据库诊断 / 实例 API 配置 | 是 | 否 | 否 | 否 |
| 查看本工作区团队 | 是（部署工作区） | 是 | 是 | 否 |
| 添加管理员 | 是（部署工作区） | 是 | 否 | 否 |
| 添加普通成员 | 是（部署工作区） | 是 | 是 | 否 |
| 修改 / 停用 / 重置管理员 | 是（部署工作区；不能操作自己/所有者） | 是（不能操作自己/所有者） | 否 | 否 |
| 修改 / 停用 / 重置普通成员 | 是（部署工作区） | 是 | 是 | 否 |
| 管理字段 / 工作流程 | 是（部署工作区） | 是 | 是 | 否 |
| 个人资料、偏好、自己的密码 | 是 | 是 | 是 | 是 |
| 本工作区 CRM、获客、邮件草稿 | 是（部署工作区） | 是 | 是 | 是 |

平台页可以查看工作区级统计和最近的管理审计；**没有跨客户模拟登录、任意浏览客户业务或账号密码的入口**。业务成员当前共享工作区全部 CRM 数据；细分到客户负责人、销售小组、单条记录的权限尚未实现。

## 4. 日常管理

- **改角色**：所有者将普通成员提升为管理员，或将管理员降级为普通成员。旧会话立即失效，新权限从重新登录生效；服务端在数据库锁内重查权限，不能依靠旧令牌继续管理。
- **停用成员**：保留业务记录，不删除客户资料；该成员不能登录，旧会话失效。重新启用后也必须重新登录。
- **重置密码**：产生新的随机临时密码，撤销旧会话，首次登录必须改密。密码以哈希保存，审计日志不保存明文。
- **成员上限**：不能降到低于当前活跃人数；并发添加和重新启用也要检查上限，不是只靠前端禁用按钮。
- **停用工作区**：平台确认后禁止整个公司的成员使用，不删除公司数据。不能停用当前平台管理工作区。重新启用也会撤销旧会话，避免先前会话自动复活。
- **重复部署**：数据库初始化默认保留已存在的密码、偏好、角色和停用状态，不会因为重启而自动改密或重新启用。只在明确使用重置参数时重置对应数据库账号的密码。

## 5. 数据隔离如何实现

- 工作区从登录会话解析，不采用前端传入的 `companyId` 作为权限依据。
- 业务、获客、邮件草稿、视频任务元数据、字段和流程配置均带 `company_id`，查询 / 更新 / 删除 / 导出限制在当前工作区。
- PostgreSQL 中的复合外键限制关联关系。例如 B 公司不能把自己的询盘绑定到 A 公司的客户。
- 并发写操作使用工作区事务锁；序号、活跃人数和重复订单 / 单证等约束在数据库中校验。
- 数据库不可用时业务返回 503，不切换为共享内存、样例数据或本地文件“假成功”。

**边界**：当前是服务端租户限定 SQL + 数据库约束，未实现 PostgreSQL RLS。数据库特权账号仍能访问所有数据；必须限制数据库凭据、运维权限和备份访问。部署管理员资料 / API 配置的本地文件尚未具备多副本一致性，生产不能随意横向扩容。

## 6. 当前不支持 / 不要误认为已可用

- 自助注册、支付、续费、订阅套餐、计费账单、邀请邮件、邮箱验证、MFA、所有权转移。
- 每个客户自己的 AI / Firecrawl / LiveKit 密钥和预算。目前共享收费外部服务仅对平台管理员开放，不能把平台余额直接分享给所有客户。
- 真正 IMAP/SMTP 收发邮件。邮件页仅保存工作区内草稿；点击不支持的发送行为会明确失败，不会对外发信。
- 租户专属 Webhook / 绑定密钥与回放保护。在方案完成前相关入口返回 503，不写共享业务数据。
- 数据库一键清空、网页恢复、跨租户 SQL 控制台。数据库页是只读诊断。

## 7. 常见问题

| 情况 | 怎么处理 |
|---|---|
| 初次登录只能打开个人中心 | 正常；先修改临时密码，再重新登录 |
| 成员添加提示人数满了 | 停用不使用的成员，或请平台管理员提高工作区上限 |
| 改角色 / 密码后需要重新登录 | 安全设计，旧会话已经撤销 |
| 页面返回 503 | 查看数据库管理、`db-init` 日志；不要用文件/内存替代生产数据库 |
| 所有者看不到 API 配置 | 正常；当前共享密钥仅平台可管理，BYOK 尚待实施 |
| 添加邮箱提示已注册 | 一个邮箱只属于一个工作区，不要直接修改数据库把账号迁到另一家客户 |

验证命令和备份恢复见 `database-management.md`；仍未完成的公网准入要求见审计整改表。
